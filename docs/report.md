Побочные эффекты разбора в markdown и как решены (модуль `ingest/normalize.py`):

| Эффект | Решение |
|---|---|
| Рамка вокруг маркированного списка становится таблицей из одной колонки | Одноколоночные таблицы разворачиваются обратно в список |
| Обычные абзацы обёрнуты в жирный курсив `**_ _**` | Обрамление снимается |
| Маркеры списка тремя видами: `-`, `•`, `?` | Приводятся к дефису |
| Абзац, перенесённый с предыдущей страницы, помечается заголовком `####` | Заголовок снимается, если первая строка страницы начинается со строчной буквы |

в чанк и режется по лимиту. Лечится увеличением `CHUNK_SIZE` до 2048 либо своим сплиттером,
который не рвёт таблицы.

## HierarchicalNodeParser + AutoMergingRetriever поверх SentenceSplitter

Чанки стали мельче, охват просел. Чтобы вернуть его без подъёма `TOP_K`, добавили двухуровневую
нарезку (родитель — страница), докстор на диск и `AutoMergingRetriever`. Охват это не вернуло:
склейка объединяет уже найденное, а не добавляет новое. При `TOP_K = 5` `page_hit_rate`
0.800 → 0.733, `fact_hit_rate` 0.867 → 0.667, `mrr` 0.589 → 0.633.

Полезным осталось: докстор наполнен (553 узла) — снят блокер для BM25, `from_vector_store`
его не наполняет.
